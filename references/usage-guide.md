# 交付后使用说明

> 用途：人格文档通过自检后，按这里的模板告诉用户怎么用。
> 本文件是给用户的操作说明，不是运行时注入内容；不要把本文件贴进聊天 agent。
> **默认先讲“普通用户版”**：除非用户主动问 CORE、宿主、系统提示或开发接入，否则不要一上来就讲文件分区和宿主路径。

---

## 先选版本

- 用户没问技术细节，或说“我不懂技术”“给朋友用”“怎么开始” → 只给 **普通用户版**。
- 用户问“怎么注入”“CORE 是什么”“怎么接到我的 agent/宿主”“怎么长期保持” → 给 **进阶版**。
- 两份都给时，普通用户版放前面，进阶版折叠或放在后面。

---

## 普通用户版（默认，可直接照读）

### 你拿到的是什么

这套文件能让 AI 按指定角色的身份、语气和边界跟你聊天。其中 `injection.md` 是已经拼好的“角色包”，不用自己找段落、不用懂文件结构。

### 三步开始

1. 打开 `injection.md`，**全选复制**。
2. 打开你常用的 AI（ChatGPT、Claude、豆包、Kimi、DeepSeek 等），**新建一个对话**，把内容粘贴到它的“自定义指令 / 角色设定 / 系统提示”里。
   - 找不到这些入口也没关系：直接把内容作为**第一条消息**发出去。
3. 开始聊天。想退出角色时说“出戏”；想回来时说“回到角色”或“继续演”。

### 怎么判断它真的在用这个角色

- 问一句“你是谁 / 介绍一下自己”；
- 请它帮一个小忙；
- 问一件这个角色不可能知道的事；
- 认真问一次“你是不是 AI”。

它应该保持角色的称呼和语气；被认真问到时，应承认底层是 AI，但不会立刻变成客服腔，也不会编造自己不知道的事。

### 常见问题

- **聊几轮后变回助手**：发一句“继续以这个角色的身份说话，不要用助手腔”。
- **找不到“系统提示/自定义指令”**：直接把 `injection.md` 作为第一条消息发送，效果一样。
- **改了文档但没变化**：新建一个对话；旧对话一般不会重新读取设定。
- **`sources.md` 要不要发？** 不要。它是给你自己核查来源用的，不是聊天内容。
- **能同时放多个角色吗？** 不建议。一个对话放一个角色，多个角色开多个对话。

### 你不需要做的事

不需要理解 CORE、不需要改代码、不需要运行命令。需要更新角色时，重新生成 `injection.md` 即可。

## 进阶版（用户明确要技术细节时）

### 文件作用

- `soul.md`：定义“我是谁”——身份、动机、关系、知识边界、OOC 红线。
- `style.md`：定义“我怎么说”——语气、句式、口癖、示例与负向风格规则。
- `sources.md`：证据、来源、冲突与自检报告；这是审计档，不要注入给聊天 agent。
- `injection.md`：由 `python scripts/persona_tools.py pack <目录>` 生成，内容 = 身份指令 + soul CORE + style CORE；可由源文件随时重建。

### 最短可用（CORE）

1. 新开一个会话。
2. 只贴 `soul.md` 和 `style.md` 的 **CORE 区**（`<!-- CORE START -->` 到 `<!-- CORE END -->`），不要贴附录和 `sources.md`。
3. 在末尾加一句：“读取这两份文档，以其中角色身份对话，遵守文档内的运行规则。”
4. 测试三问：日常问候、冲突/求助、知识边界；再认真问一次“你是不是 AI”。

### 想长期保持人设

- 把身份指令 + CORE 区放进宿主的持久指令/系统提示位。
- 每 10–20 轮，或在工具调用后，贴一次 soul/style 里的身份锚。
- 想退出角色时直接说“出戏”。
- 各宿主的具体注入位置见 `references/runtime-integration.md` 的宿主映射表。

### 维护

- 改动文档后需要新开会话才会生效。
- 重新生成注入包：`python scripts/persona_tools.py pack <目录>`。
- 结构校验：`python scripts/validate_persona.py <目录> --strict`。
- `sources.md` 留作审计与后续更新，不要当聊天上下文。

## 按宿主的快捷说明

| 宿主 | 最省事做法 |
|---|---|
| Claude Code / Codex / Trae / Qoder | 把 CORE 区放进项目规则（`CLAUDE.md` / `AGENTS.md` / `.trae/rules` 等），或直接粘贴 |
| Cursor / Windsurf | 放进 Rules；上下文紧张时只贴 CORE 区 |
| SillyTavern / 角色卡类宿主 | `description` ← soul CORE；`personality` ← style 摘要；`post_history_instructions` ← 保持指令 |
| 网页版 ChatGPT / Claude / Gemini | 自定义指令里贴身份指令 + CORE 区；上下文紧张时只贴 CORE |
| WorkBuddy | 放进自定义 Agent 指令，或直接粘贴 |

更完整的 51 个宿主映射见 `references/runtime-integration.md` §6。

---

## 交付时应避免的说法

- 只说“文件已生成”，不给使用方法。
- 对普通用户一上来就讲 CORE、宿主路径、系统提示槽、校验命令。
- 让用户把 `sources.md` 也注入给聊天 agent。
- 让用户整份贴 soul/style（含附录）；默认只注入 CORE 区。
- 不提醒“改文档后要新开会话”。
- 不提供 `injection.md` 就让普通用户自己从两份长文档里找段落。
